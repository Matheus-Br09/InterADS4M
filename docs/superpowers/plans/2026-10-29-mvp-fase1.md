# MVP Fase 1 (pronto para publicar) — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deixar o site da ONG SOS pronto para publicar: doação Pix e voluntariado sem login, painel de gestão enxuto no React, superfície pública sem dados pessoais, e passo a passo de deploy na Hostinger escrito.

**Architecture:** Backend Laravel continua servindo a API em `/api/v1` (rotas em `backend/routes/integracao.php`); tudo que é de apoiador logado/apadrinhamento sai das rotas. O painel de gestão passa a ser **só no React** (`/gestao/*`), usando o login existente (`auth/entrar`) restrito a `tipo_usuario = admin`; o painel Blade é removido. Dados da ONG (chave Pix, WhatsApp, e-mail da gestão) vêm de `config/ong.php` ← `.env`.

**Tech Stack:** Laravel 13 / PHP ^8.3 / MySQL 8 / PHPUnit 12; React 19 + Vite + Tailwind 4 + react-router 7; testes de frontend com `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-29-mvp-lancamento-design.md`

## Global Constraints

- Sem segredos no código: chave Pix, WhatsApp, Instagram, e-mail da gestão e SMTP só via `.env` → `config/ong.php` / `config/mail.php`. Nunca ler nem imprimir o `.env` real.
- Nenhum endpoint público pode devolver dado pessoal (voluntário, doador, criança, apoiador).
- Voluntário: só maiores de 18 anos, validado no frontend **e** no backend.
- Pix: confirmação manual pela gestão; pendentes expiram após **7 dias**.
- Nenhuma biblioteca nova, exceto `qrcode` (npm) na Task 13 — **pedir OK do usuário antes de instalar**.
- Textos visíveis ao público e ao gestor em português do Brasil, linguagem simples; nada de "teste", "seed", "intenção vinculada à sua conta".
- Commits pequenos, um por task, no branch `mvp-lancamento`. Perguntar ao usuário antes do primeiro commit (preferência dele); nunca fazer push.
- Comandos: backend `cd backend && php artisan test` ; frontend `cd inter-ong && npm test && npm run lint && npm run build`.

## Review Focus

1. **Chave Pix não configurada** (`ONG_PIX_CHAVE` vazio) → `POST /doacoes` responde 503 "Doações por Pix estão temporariamente indisponíveis" e não grava nada; o site mostra essa mensagem em vez de uma chave vazia. (Task 3)
2. **Aniversário de 18 anos exatamente hoje** → aceito; um dia a menos → recusado, no backend e no utilitário do frontend. (Tasks 7 e 14)
3. **SMTP fora do ar** → doação e voluntário continuam sendo gravados e respondendo sucesso; o erro do e-mail só vai para `report()`. (Task 6)
4. **Gestor desativado com sessão aberta** → a próxima chamada a `/gestao/*` responde 401/403. (Task 10)
5. **Valor digitado com vírgula** ("50,00") → o frontend normaliza para `50.00` antes de enviar; o backend recusa formato inválido com 422 e mensagem clara. (Tasks 3 e 13)
